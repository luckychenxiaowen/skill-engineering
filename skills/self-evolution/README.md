# self-evolution · 用完之后的复盘与迭代

解决**「一个 Skill 用过之后，到底该改、该留、还是该忘」**：用五维评分把主观感觉变成可比较的记录，再决定写入长期记忆、放进临时验证区，还是直接丢弃。

## 什么时候用它

- 一个 Skill 用了几次，说不清是变好还是变坏
- 想把「这次好用」沉淀成可复用的规则，而不是凭印象
- 长期记忆越攒越杂，需要一套写入与遗忘的判据

## 怎么用

1. 整目录复制进你的 Agent 的 `skills/` 目录
2. 用完某个 Skill 后说「复盘一下刚才那个 Skill」
3. 按 `SKILL.md` 的五步闭环走：五维评分 → 处理决策 → 可信度标注 → 五标准判断 → 写入长期记忆 / 临时验证区 / 遗忘

`SKILL.md` 内含主动触发、被动触发、L2 可信度标注、临时验证区与遗忘规则；`references/` 下是三份可直接填的模板：

| 文件 | 用途 |
|---|---|
| `references/eval_template.md` | 五维评分表 |
| `references/failure_patterns.md` | 五种常见失败模式及案例 |
| `references/taste_filter_template.md` | 判断标准 / 口味过滤器模板 |

无依赖、无配置、不需要联网。

## 与本仓其他 Skill 怎么配合

| 顺序 | 用什么 | 得到什么 |
|---|---|---|
| 1 | `skill-writer` | 写出一份 Skill |
| 2 | `skill-detector` | 发布前打分、找短板 |
| 3 | 真实用一次 | 实际效果记录 |
| 4 | **本 Skill** | 改 / 留 / 沉淀的决策记录 |

## 边界

- 这是**记录与决策模板**，不会自动修改你的 Skill 或记忆；写入动作由使用者执行。
- 五维评分是辅助判断，不是客观测量；分数不可跨场景横比。
- 「写入长期记忆」的五条标准是为了防污染，宁可不写也别写错。

## 来源与文件

个人自研（AI 辅助创建），无第三方代码。本目录含 `SKILL.md` + `references/` 三份模板。仓根 [ATTRIBUTION.md](../../ATTRIBUTION.md) 记录了本仓全部第三方来源（本 Skill 无）。
