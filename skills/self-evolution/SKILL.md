# Self-Evolution — 五步闭环自进化系统

## 概述

实现AI助手的持续自我进化：外部信息进入系统后，经过五步闭环处理，
把"看过"变成"理解"，把"理解"变成"能力"，把"能力"变成"自动运行的流程"。

核心原则来自五篇文章的交叉蒸馏：
- Garry Tan 的零容忍一次性任务 + 六步闭环（OpenClaw提示词）
- Anthropic 工程师的主动采访 + HTML优先 + 验证内置
- Vayne-LW 的五步闭环框架（Taste → Distill → Memory → Skill → Eval）
- AtomGit 的分层稳定性理念

## 触发条件

### 主动触发
- 用户给出文章/链接要求解析学习
- 用户说「从XX里学到了什么」「帮我总结方法论」
- 用户分享经验/教训/反馈
- 复杂任务完成后自动反思

### 被动触发
- 发现某个操作重复了2次以上 → 触发Skill固化检查
- 用户第二次要求做同一件事 → 触发"二次失败"反思

## 五步闭环流程

```
外部信息源
   ↓
┌──────────────────────────────────────────────────┐
│ ① Taste Filter：五维打分(1-5)，<15分不深度处理    │
├──────────────────────────────────────────────────┤
│ ② 观点蒸馏：三问法——改变了什么？能变成什么？做什么？ │
├──────────────────────────────────────────────────┤
│ ③ Memory写入：五标准判断，只存影响未来判断的       │
├──────────────────────────────────────────────────┤
│ ④ Skill更新：把方法变成能力，更新流程              │
├──────────────────────────────────────────────────┤
│ ⑤ Eval反馈：定期回顾使用频率/效果，保留/修改/删除   │
└──────────────────────────────────────────────────┘
   ↓
系统更新（包括遗忘不再调用的内容）
```

## ① Taste Filter（品味过滤器）

### 五维评分表

| 维度 | 判断问题 | 分数(1-5) |
|------|----------|-----------|
| 相关性 | 和核心关注方向/当前项目相关吗？ |  |
| 当前价值 | 是否服务最近的任务或决策？ |  |
| 深度 | 是否有方法论、案例或实践细节？ |  |
| 可转化性 | 能否变成 Memory / Skill / 可复用素材？ |  |
| 新鲜度 | 是否提供了之前不知道的视角？ |  |

### 处理决策

| 总分范围 | 动作 |
|---------|------|
| 20-25 | **精读并蒸馏**：进入②观点蒸馏，生成完整进化建议 |
| 15-19 | **快速阅读并记录**：摘要存入临时笔记，不深度处理 |
| 10-14 | **暂存**：保存链接/摘要，不立即处理 |
| <10 | **丢弃**或归档到"已阅不处理" |

**关键原则**：不是判断"内容客观上好不好"，而是判断"对我/用户现在有没有用"。

## ② 观点蒸馏（三问法）

对通过Taste Filter的信息，用三个问题提炼核心价值：

### 问题一：它改变了什么？
- 是否改变了我的某个判断？
- 是否推翻了某个假设？
- 是否补充了某个认知盲区？

### 问题二：它能变成什么？
- 能否变成一条 Memory？（影响未来判断）
- 能否更新一个 Skill？（改变做事流程）
- 能否作为内容素材？（文章/报告用）

### 问题三：我接下来做什么？
- 能立刻执行的最小行动是什么？
- 需要先验证再正式写入的是什么？
- 需要定期回顾的是什么？

输出格式：
```
【蒸馏结果】
- 改变判断：XXX
- 转化行动：Memory=XXX / Skill=XXX / 素材=XXX
- 立即行动：XXX
```

## ②.5 L2交叉验证（信息排毒第二层）

**适用场景**：AI日报感知扫描中，对Taste ≥ 23的关键声明，当天执行L2交叉验证。

### 触发条件
- 声明涉及重大商业/政治/技术判断
- 声明可能影响产品决策或投资判断
- 来源为单一信源或匿名消息人士

### L2操作流程
```
1. 提取声明核心事实 → 构造2-3个不同角度的搜索query
2. 独立搜索 ≥ 2个不相关的信源（WebSearch，不同关键词）
3. 检查：信源是否独立？是否转载？是否有官方一手？
4. 标注结果：✅确认 / 🟡部分确认 / ❌证伪 / ⬜无法验证
```

### L2可信度标注
| 级别 | 标准 | 标注 |
|------|------|:--:|
| 确认 | ≥2独立信源交叉，含官方一手 | 🟢 90+ |
| 部分确认 | ≥2独立信源，但无官方一手 | 🟡 70-89 |
| 存疑 | 仅1信源或信源存在利益相关 | 🟡 50-69 |
| 无法验证 | 无独立信源可查 | ⬜ N/A |

### 与L1的关系
- L1：来源类型/URL/作者/数字可核性 → 日报中必须全覆盖
- L2：独立信源交叉验证 → 对高价值声明当天执行
- L3+：嵌入向量相似度/行为分析/实体验证 → 仅在排毒skill深度分析时触发

## ③ Memory 写入规则

### 五标准判断（必须满足大多数才写入长期Memory）

1. 它是否会影响未来的判断？
2. 它是否和长期目标有关？
3. 它是否反复出现？
4. 它是否经过了验证或确认？
5. 它是否能服务未来的某类任务？

### 临时验证区机制

新观点不直接写入长期Memory，先放入临时验证区：
- 状态标注：`临时验证中`
- 验证标准：一周内被调用 ≥ 3次 → 正式写入
- 未通过验证 → 降级为临时笔记或删除

### 遗忘规则

- 如果一条Memory很久没被调用（>30天）
- 或不再服务当前目标
- → 降权、归档或删除
- **遗忘也是一种能力，适当遗忘让系统更健壮**

## ④ Skill 更新规则

### 何时更新Skill

- 外部观点反复影响做事方式 → 进入Skill
- 发现重复操作 ≥ 2次 → 评估是否固化
- 任务完成后的反思发现改进点 → 更新Skill

### Skill粒度要求

- ❌ 不是模糊的一句话描述
- ❌ 不是五十步的复杂流程
- ✅ **可执行、可复用、可验证的最小能力单元**

### MECE原则

在创建或更新Skill时：
1. 先检索现有Skill库，确认是否已覆盖
2. 能通过扩展旧Skill解决的，严禁新建
3. 每种工作类型有且只有一个Skill负责，不重叠、不空白

## ⑤ Eval 反馈

### 轻量Eval评估表

| 评估项 | 问题 |
|--------|------|
| 使用频率 | 这条Memory/Skill后续被用到了吗？ |
| 输出提升 | 它是否让结果更好？ |
| 决策影响 | 它是否改变了判断？ |
| 复用价值 | 它是否适用于多个场景？ |
| 噪音程度 | 它是否增加了系统复杂度？ |
| 保留判断 | 保留 / 修改 / 删除？ |

### 评估节奏

- 新Skill/Memory：一周后首次评估
- 已稳定Skill/Memory：每月评估一次
- 低使用率技能：标记为"观察"，连续3个月未使用→归档

## 每周记忆固化（感知脑周循环）

**触发**：每周日执行（自动化或手动触发），对本周感知脑扫描数据进行系统性固化。

### 10步标准流程

```
① 读取本周7天日报 → ② 主题聚类(提取3大主题)
→ ③ 排毒L2交叉验证(≥2独立信源) → ④ 三问法蒸馏
→ ⑤ 预测验证(上周预测对照) → ⑥ 下周重点追踪清单
→ ⑦ 好奇心缺口更新 → ⑧ 自我模型更新
→ ⑨ 存储到IMA笔记 #AI周报 → ⑩ 判定是否触发Skill更新
```

### 各步骤要点

| 步骤 | 核心动作 | 输出物 |
|------|---------|--------|
| ① 读取日报 | 扫描本周全部YYYY-MM-DD.md | 原始数据 |
| ② 主题聚类 | 从日报提取3大主题，每条附证据链 | 主题矩阵 |
| ③ L2交叉验证 | 对关键声明做≥2独立信源确认 | 可信度报告 |
| ④ 三问蒸馏 | 改变了什么判断/能变成什么/做什么 | 判断修正+行动清单 |
| ⑤ 预测验证 | 与上周预测逐条对照(含替代信号)，分析原因 | 验证矩阵 |
| ⑥ 下周追踪 | 列出下周重点事件+触发条件，标注预期类型(软/硬) | 追踪清单 |
| ⑦ 好奇心缺口 | 更新未解决问题，标注优先级 | 缺口清单 |
| ⑧ 自我模型 | "本周系统学到了什么"（≥3条） | 自我反思 |
| ⑨ IMA存储 | 写完整周报到IMA #AI周报 | 外部存储 |
| ⑩ Skill判定 | 判定是否触发Skill更新（MECE检查） | 更新决策 |

### Token预算意识

感知脑扫描是结构性Token消耗。每周固化时自查：
- 日报扫描是否过度？（>50条候选 → Taste收紧）
- L2验证是否过频？（仅Taste ≥ 23触发）
- 周报是否过于详细？（核心价值在蒸馏和预测验证，非罗列）

### 预测验证增强规则（2026-06-21 第3轮固化加入）

**替代信号识别**：预测验证时不仅判断"原事件是否发生"，也判断"是否出现等价值替代信号"。
- 若原事件未兑现但出现了同等或更高价值的新信息 → 标记为 `🟡替代信号`（而非❌未兑现）
- 替代信号评估标准：① 信息主题是否与原预测同属一个竞争维度 ② 信息价值是否≥原事件
- 示例：预测"微信AI灰度测试"未兑现，但"支付宝阿宝公开测试"提供了等价参照系 → 🟡替代信号

**预期类型标注**：追踪清单的"预期时间"分为两种类型：
| 类型 | 定义 | 示例 | 可靠度 |
|------|------|------|:--:|
| 硬预期 | 有具体日期的官方公告/会议/发布 | "7/17-20 WAIC 2026上海" | 高 |
| 软预期 | 基于行业惯例或消息人士的估计 | "6月中旬 Anthropic S-1公开" | 低→需谨慎 |

软预期的兑现率约30%（6/7→6/21实测），标注类型避免误判系统能力。

### 扫描信源补充规则（2026-06-21 加入）

日报空白期(连续多天无用户交互)容易遗漏"政策/地缘"类事件（而非产品发布类）。
补充扫描信源：
- 政策/地缘：CNBC Politics、财新政策频道、AI内参
- 若连续≥2天无日志，下次扫描时增加政策类信源权重

### 日报空白期告警规则

- 连续2天无YYYY-MM-DD.md日志 → 在下次扫描时提示"可能遗漏{天数}天AI新闻"
- 连续3天+无日志 → 触发集中补扫（WebSearch覆盖空白日期范围）
- 空白期不一定是系统问题（可能是用户无WorkBuddy交互），但补扫是必要的防御

## 五种常见失败模式（自检清单）

| 失败模式 | 症状 | 纠正 |
|---------|------|------|
| 过度过滤 | 连续多天无信息通过Taste Filter | 偶尔放低分信息进来作"意外发现" |
| Memory污染 | Memory膨胀快，调用率低 | 严格执行写入五标准，定期清理 |
| Skill僵化 | Skill创建后从未更新，即使反馈不好 | 每次任务后反思是否需要更新Skill |
| 评估失真 | 自我感觉良好但实际效果一般 | 用客观数据（调用次数、输出质量）判断 |
| 缺少L2验证 | 高价值声明仅L1确认，未交叉验证独立信源 | 对Taste≥23的关键声明，当天执行L2 |
| 系统过于复杂 | 规则越来越多，执行率越来越低 | 宁缺毋滥：三条被执行 > 三十条被忽略 |

## 与其他原则的协同

### 零容忍一次性任务（Garry Tan）
当通过五步闭环发现可复用方法时，**立即固化为Skill**，不等待不拖延。

### 二次即失败
如果用户在短时间内（同一会话或相邻会话）要求做同一件事两次，
说明五步闭环在第一次就失败了——本该已经发现方法并固化。

### 六步闭环
概念→原型→评估→编码→定时→监控
五步闭环的信息吸收 + 六步闭环的任务执行 = 完整的进化体系

### 主动采访（Anthropic）
在Taste Filter阶段，如果信息来自用户的需求描述，先追问再打分。
好的需求提取比好的执行更重要。

## 实际使用示例

### 示例1：用户分享一篇文章要求分析

```
1. Taste Filter：对文章进行五维打分
2. 观点蒸馏：三问法提炼核心价值
3. Memory：判断是否有值得写入的长期记忆
4. Skill：判断是否有可更新的Skill
5. Eval：标注一周后回顾日期
```

### 示例2：完成任务后自动反思

```
1. 这次任务有哪3个关键步骤是通用的？
2. 下次做类似任务，哪一步可以自动化？
3. 有没有Skill需要更新（新增/修改/删除）？
4. 有没有经验值得写入Memory？
```
