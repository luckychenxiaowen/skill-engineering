# 五种失败模式及案例

## 1. 过度过滤
**症状**：连续多天没有信息通过Taste Filter
**案例**：设置了过高的门槛（全部要4分以上），导致错过了跨界但有启发的内容
**纠正**：偶尔放低分信息进来，作为"意外发现"通道。每周保留1-2条低分但有趣的内容

## 2. Memory污染
**症状**：Memory文件快速增长，大部分内容从未被调用
**案例**：把所有对话精华都存入Memory，结果Memory变得和聊天记录一样长，反而找不到关键信息
**纠正**：严格执行五标准，只有影响未来判断的才写入。定期清理30天未调用的条目

## 3. Skill僵化
**症状**：Skill创建后从未更新，即使使用体验不好
**案例**：一个写作Skill创建了3个月，但每次用都要手动调整，却从未更新Skill本身
**纠正**：把Skill更新当作和代码重构一样正常的操作。每次使用后反思是否需要改进

## 4. 评估失真
**症状**：自我感觉良好，但实际效果一般
**案例**：觉得某个Skill很好用，但统计发现它3周只被调用了1次
**纠正**：用客观数据（调用次数、输出质量评分）而非主观感受判断效果

## 5. 系统过于复杂
**症状**：规则越来越多，自己都记不住，执行率下降
**案例**：Memory写入规则从5条扩展到15条，结果一条都严格执行不了
**纠正**：宁缺毋滥。三条被严格执行的规则 > 三十条被忽略的规则
