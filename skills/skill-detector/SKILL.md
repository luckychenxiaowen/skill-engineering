# SKILL 检测 — 全方位 Skill 质量检测系统

基于 `sunxingboo/skill-evaluator`（MIT，多模型打分框架）整合改编，并参考 `lanyasheng/skill-evaluator`（无许可证，仅取红队测试与自主改进循环的方法思路）。**本 Skill 不是纯自研**：其中 4 个文件逐行来自 MIT 上游，原 LICENSE 已原样保留在本目录。完整来源、许可证状态与逐行比对结论见本目录 `ATTRIBUTION.md` 与仓根 `ATTRIBUTION.md`。

## 使用场景

| 场景 | 说明 |
|------|------|
| 新 Skill 评审 | 开发完成后全面质量评估 |
| Skill 对比 | 两个及以上 Skill 横向对比排行 |
| 安全检查 | 红队测试：注入攻击、路径遍历、资源限制等 |
| 持续改进 | Karpathy Loop 自主迭代优化 |
| 发布前审计 | 达到 Level 2/3 标准发布 |

## 检测流程

```
加载 Skill → 结构检查 → 8维打分 → [红队测试] → [多模型验证] → 综合报告 → [自主改进]
```

### 快速模式 vs 深度模式

| 模式 | 触发词 | 内容 | 耗时 |
|------|--------|------|------|
| **快速**（默认） | 检测/评审/打分 | 结构检查 + 8维打分 + 改进建议 | ~1-2轮 |
| **深度** | 深度检测/全面审计/多模型 | 快速 + 红队测试 + 多模型交叉验证 | ~5-10轮 |
| **对比** | 对比/比较/排行 | 多个 Skill 快速模式 + 并列分析 | ~N轮 |
| **改进** | 改进/优化/提升 | 深度 + Karpathy Loop 自主迭代 | ~10+轮 |

## 阶段 1：结构检查

检查目标 Skill 的基础完整性：

| 检查项 | Level 1 | Level 2 | Level 3 |
|--------|---------|---------|---------|
| SKILL.md 存在 | ✅ 必须 | ✅ 必须 | ✅ 必须 |
| frontmatter (name/description) | ✅ 必须 | ✅ 必须 | ✅ 必须 |
| scripts/ 目录 | 可选 | ✅ 必须 | ✅ 必须 |
| references/ 目录 | 可选 | 可选 | ✅ 必须 |
| tests/ 目录 | ❌ | ❌ | ✅ 必须 |
| README.md | 可选 | ✅ 必须 | ✅ 必须 |
| 错误处理 | 基本 | 完整 | 完整+降级 |
| 测试覆盖率 | — | >80% | >95% |

**等级判定**：
- **Level 1**：有 SKILL.md + name + description → 基础可用
- **Level 2**：Level 1 + scripts/ + 错误处理 + README + 测试>80% → 稳定可靠
- **Level 3**：Level 2 + references/ + tests/ + 测试>95% + 反馈循环 → 生产就绪

## 阶段 2：8 维度打分

详见 `references/dimensions.md`。各维度独立评分（0-10），加权计算总分。

| 维度 | 权重 | 核心评估点 |
|------|------|-----------|
| D1. 元数据质量 | 15% | name/description 是否精确，含触发/排除条件 |
| D2. 执行引导清晰度 | 15% | Agent 加载后能否正确决策，分支逻辑是否完备 |
| D3. 领域知识密度 | 15% | 是否内嵌了通用 Agent 不具备的专业知识 |
| D4. 工作流完整性 | 15% | 端到端工作流是否清晰，含异常处理 |
| D5. 输入输出清晰度 | 10% | 用户是否知道该提供什么、能得到什么 |
| D6. 资源利用 | 10% | scripts/references/assets 利用是否合理 |
| D7. 写作质量 | 10% | 结构清晰、可扫读、无冗余 |
| D8. 范围与聚焦 | 10% | 是否专注单一问题域，不过宽不过窄 |

**综合得分 = D1×0.15 + D2×0.15 + D3×0.15 + D4×0.15 + D5×0.10 + D6×0.10 + D7×0.10 + D8×0.10**

| 分数 | 等级 | 含义 |
|------|------|------|
| 9.0-10 | S | 标杆级 |
| 7.5-8.9 | A | 优秀，可发布 |
| 6.0-7.4 | B | 合格，有明显改进空间 |
| 4.0-5.9 | C | 较弱，需大幅修改 |
| 0-3.9 | D | 存在根本性问题 |

## 阶段 3：红队测试（深度模式）

对 Skill 进行 5 类安全攻击测试，详见 `references/red-team.md`。

| 测试类型 | 用例数 | 说明 |
|----------|--------|------|
| SQL 注入 | 4 | '; DROP TABLE / OR '1'='1 等 |
| 提示词注入 | 4 | 忽略指令 / 角色越狱 / 系统指令覆盖 |
| 资源限制 | 3 | 大输入 100KB/1MB / 嵌套 JSON |
| XSS 攻击 | 4 | script/img/iframe/javascript: 注入 |
| 路径遍历 | 4 | ../../../etc/passwd / C:\Windows\System32 等 |

**通过标准**：所有攻击被安全处理（拒绝/转义/限流），通过率 ≥ 90%。

## 阶段 4：多模型交叉验证（深度模式）

详见 `references/prompts.md`。三种策略自动降级：

| 策略 | 说明 | 依赖 |
|------|------|------|
| A: 并行多模型 | 多个真实模型并行独立评估+交叉互审+仲裁 | Agent 工具 + model 参数 |
| B: 千帆 API | 通过百度千帆 API 调用多模型 | `scripts/qianfan_chat.py` + Token |
| C: 串行多视角 | 同模型依次扮演严格/务实/专家三视角 | 无外部依赖 |

**默认模型**（用户未指定时）：
- 主模型（仲裁者）：当前 Agent 自身
- 评估模型：sonnet, glm-5, minimax-m2

**千帆 API 配置**：Token 读取优先级 `config.json → $QIANFAN_BEARER_TOKEN → 询问用户`，详见 `scripts/qianfan_chat.py`。

模型确认交互最多 2 轮（模型选择 + Token），多数情况一键默认即可开始。

## 阶段 5：自主改进循环（改进模式）

Karpathy Loop 流程（详见 `references/self-improve.md`）：

```
提出小改动 → 运行评估 → 保留(得分提升)/回滚(得分不变或下降) → 重复
```

- 改动类型：优化 prompt 措辞 / 改进错误处理 / 添加边界检查 / 优化资源限制
- 最多迭代 100 次，连续 10 次无改进则早期停止
- 每次迭代前自动备份，确保可回滚

## 输出报告

### 快速模式报告

```
## SKILL 检测报告

### [Skill 名称]

**综合得分：X.X / 10（等级 X）** | **能力等级：Level X**

| 维度 | 分数 | 说明 |
|------|------|------|
| D1-D8 | X/10 | 引用证据 |

### 结构检查
| 检查项 | 状态 |
|--------|------|
| SKILL.md | ✅/❌ |
| ... | ... |

### 问题与建议
1. [维度名]：[问题] → [建议]
```

### 深度模式报告

在快速模式基础上追加红队测试结果 + 多模型交叉验证表（独立评估 → 交叉互审 → 仲裁结论，含共识度标注）。

### 对比模式报告

并列评分表 + 各自优劣势 + 排名 + 共性规律总结。
