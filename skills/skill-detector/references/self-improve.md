# Karpathy Loop 自主改进指南

借鉴 Karpathy autoresearch 思想，通过「小改动 → 评估 → 保留/回滚」循环，自动优化 Skill 质量。

## 核心流程

```
备份 Skill → 初始评估 → [提出小改动 → 运行评估 → 保留或回滚] × N → 生成报告
```

## 改动类型

| 类型 | 说明 | 示例 |
|------|------|------|
| 优化 prompt 措辞 | 让 instructions 更精确 | "必须" → "必须且仅当..." |
| 改进错误处理 | 补充异常分支 | 添加 "当用户输入不完整时，追问..." |
| 添加边界检查 | 输入验证和资源限制 | 添加 "输入超过 10KB 时拒绝" |
| 优化资源限制 | 调整 token/timeout 等 | "max_tokens: 4096" → "max_tokens: 8192" |

## 参数配置

| 参数 | 默认值 | 说明 |
|------|--------|------|
| --metric | accuracy | 优化指标：accuracy/reliability/efficiency/cost/coverage |
| --max-iterations | 100 | 最大迭代次数 |
| --early-stop | 10 | 连续无改进次数上限，达到则停止 |

## 决策规则

1. **保留**：新得分 > 当前最佳得分 → 提交改动，更新最佳得分
2. **回滚**：新得分 ≤ 当前最佳得分 → 恢复到备份，无改进计数 +1
3. **早期停止**：连续 10 次无改进 → 停止
4. **趋势预警**：最近 5 次迭代得分下降 > 5% → 警告并询问用户

## 安全机制

- 每次迭代前自动备份整个 Skill 目录
- 改动类型限制为「小改动」，避免破坏性变更
- 所有改动可通过备份回滚
- 运行结束后自动清理备份

## 经验数据

实测 5 次迭代可带来约 16.3% 的改进幅度。最佳实践：

- 从 D2（执行引导清晰度）和 D5（输入输出清晰度）开始，这两个维度最易改进
- 每次迭代只改一个维度，避免交叉干扰
- 改动后立即评估，不要累积多个改动再评估

## 改进趋势判断

| 趋势 | 判断条件 | 行动 |
|------|---------|------|
| 上升 | 最近 5 次 > 之前 5 次 × 1.05 | 继续当前策略 |
| 平稳 | 变化 < 5% | 考虑调整策略或换维度 |
| 下降 | 最近 5 次 < 之前 5 次 × 0.95 | 回滚到最佳版本，换策略 |
